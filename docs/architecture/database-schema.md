# Database Schema

Source of truth is the code, not this doc: `packages/db/src/schema/*.ts` (19 files, exported via `index.ts`). This page orients — for exact columns, types, enums, and indexes, read the schema file for the domain you're touching. RLS policies live in `packages/db/src/schema/rls.ts`; the `FORCE ROW LEVEL SECURITY` migration is `packages/db/migrations/0001_force_row_level_security.sql`.

## ID convention

Every table's primary key is `uuid("id").primaryKey().default(sql\`uuidv7()\`)`— the`id()`helper in`columns.ts`. This is a native Postgres 18 `uuid`column with a DB-level`uuidv7()` default (time-ordered, index-friendly), replacing the old ULID-as-text convention. Almost every foreign-key-shaped column (`orgId`, `landingPageId`, `userId`, ...) is `uuid` too.

**Exceptions that stayed `text`** — anything that isn't one of our own row ids:

- External-system ids: `customDomains.cfHostnameId` (Cloudflare), `tiktokConnections.subscriptionId`, `emailLogs.resendId` (Resend), `payments.providerTxId` (payment provider tx id)
- DOM/client-generated ids: `studioComments.srcmapId` (srcmap engine element id, not a DB row), `events.anonymousId` (landing-runtime's client-side localStorage id)
- Catalog/PageSpec keys: `auditFindings.elementId`, `eventDefinitions.elementId`/`componentId` (PageSpec element/component keys, not rows)
- Human-readable slugs: `campaigns.publicId`

## Multi-tenancy / RLS

Tenant isolation is enforced at the Postgres level, not just in app code (defense-in-depth — architecture.md §6). Two building blocks in `rls.ts`:

- **`orgIsolationPolicy()`** — `for: "all"`, requires `org_id = current_setting('app.current_org')::uuid` on read and write. `NULLIF(..., '')` guards an unset GUC so the policy fails closed (no session var set → no rows), not open.
- **`platformReadPolicy()`** — `for: "select"` only, lets platform staff read cross-tenant when `app.is_platform_admin = 'true'`. Postgres ORs permissive policies together, so this adds a read path without touching writes — every write still goes through `withOrgScope(targetOrgId, ...)`, there is no cross-tenant write bypass.
- **`orgOrPlatformReadPolicy()`** — variant for tables where `org_id IS NULL` means "platform-curated, visible to every tenant" (e.g. platform-wide skills/prompt templates).

A table opts in with `.enableRLS()` plus one of the policies above in its index definition, and must be added to migration `0001_force_row_level_security.sql`'s `ALTER TABLE ... FORCE ROW LEVEL SECURITY` list (Postgres exempts the table owner from RLS unless FORCE is set — without it the policy is a no-op for whichever role runs migrations).

**Known gap**: several tables carry `orgId` but have no RLS policy / `.enableRLS()` today — notably `businessProfiles`, `strategyBriefs`, `products`, `campaigns`, `landingPages`, `pageVersions`, `pageAssets`, `deployments`, `customDomains`, `aiUsage`, `emailLogs`, `optimizationHypotheses`, `auditRuns`/`auditFindings`, `eventDefinitions`, `events`, `leadActivities`. Isolation for these currently relies on app-layer `withOrgScope` query scoping only. Worth confirming with the team whether this is deliberate (append-only/low-risk tables) or backlog.

## Tables by domain

**Auth** (`auth.ts`) — Better Auth's own tables, org layer bolted on separately (not generated by the org plugin): `user`, `session`, `account`, `verification`.

**Core / org** (`core.ts`) — `organizations` (plan, AI credit balance, disable flag), `memberships` (org+user+role), `invites`, `auditLogs` (tenant-scoped action trail).

**Platform** (`platform.ts`) — cross-tenant staff, separate from `memberships`: `platformStaff` (support/billing_ops/platform_admin), `platformAuditLogs` (every `/platform/*` action). No RLS — these tables have no tenant boundary.

**CRM / leads** (`crm.ts`, largest file) — `leads`, `assignmentRules` (routing engine config), `savedViews` (filter presets), `webhookCredentials` + `notifyCredentials` (BYOK secrets, AES-256-GCM encrypted), `leadActivities`, `consents` (NĐ 13/2023 compliance), `orders`, `payments`, `paymentConnections` (non-custodial — org's own provider), `unmatchedTransactions`, `dataSubjectRequests`, `refundRequests`, `webhookDeliveryFailures` (retry/dead-letter), `tiktokConnections` (OAuth lead-ads integration).

**Catalog** (`catalog.ts`) — `products`, `campaigns` (has `publicId` slug), `campaignProducts` (join).

**Business / strategy** (`business.ts`) — `businessProfiles`, `strategyBriefs` — one JSONB blob per section rather than a wall of columns; shapes live in `@dv/contracts`.

**Studio / landing pages** (`studio.ts`) — `landingPages`, `pageVersions` (either legacy srcmap `htmlKey`/`srcmapKey` or native `spec` JSONB PageSpec — mutually exclusive by `source`), `pageAssets`, `entityImages` (org logo / campaign OG image, RLS+`enableRLS`), `studioComments`, `chatSessions`, `chatMessages` (RLS+`enableRLS`).

**Custom import** (`custom-import.ts`) — `customPageBundles`, per-import-cycle bookkeeping for raw-HTML imported pages.

**Publishing** (`publishing.ts`) — `deployments` (one "live" row per hostname, enforced by a partial unique index), `customDomains`, `publishOutbox` (hostname→deployment apply queue).

**AI** (`ai.ts`) — `aiConnections` (BYOK provider keys, RLS+`enableRLS`), `aiUsage`, `skills` (org or platform-wide, RLS+`enableRLS`), `promptTemplates` (RLS+`enableRLS`), `promptTestRuns` (RLS+`enableRLS`), `landingSkills` (per-page skill override).

**Quality** (`quality.ts`) — `auditRuns`, `auditFindings` (rule-level results; scores are a summary of these).

**Optimization** (`optimization.ts`) — `optimizationHypotheses` — human-approved only, nothing auto-publishes off one.

**Tracking** (`tracking.ts`) — `eventDefinitions` — regenerated (delete+insert) on every structural PageSpec change, only current version's registry is kept.

**Analytics** (`analytics.ts`) — `events` — append-only, written from the edge beacon.

**Billing** (`billing.ts`) — `featureFlags`, `planFeatures` (keyed by the `organizations.plan` enum, no separate plans table), `orgFeatureOverrides` (per-org override, RLS+`enableRLS`).

**Email** (`email.ts`) — `emailLogs`.

**Templates** (`templates.ts`) — `templates` — shared across all orgs, no `org_id`, no RLS.
